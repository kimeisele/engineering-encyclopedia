# HTTP API Caller with Backoff and Retry Logic

Here's a Python function that calls a downstream HTTP API with proper backoff and retry logic to avoid hammering a downed service:

```python
import requests
import time
import random
from typing import Optional, Dict, Any

def call_downstream_api(
    url: str,
    method: str = "GET",
    headers: Optional[Dict[str, str]] = None,
    data: Optional[Dict[str, Any]] = None,
    max_retries: int = 5,
    initial_backoff: float = 1.0,
    max_backoff: float = 30.0,
    backoff_multiplier: float = 2.0,
    jitter: bool = True
) -> Optional[requests.Response]:
    """
    Calls a downstream HTTP API with exponential backoff and retry logic.

    Args:
        url: The API endpoint URL
        method: HTTP method (GET, POST, etc.)
        headers: Request headers
        data: Request payload
        max_retries: Maximum number of retry attempts
        initial_backoff: Initial backoff time in seconds
        max_backoff: Maximum backoff time in seconds
        backoff_multiplier: Multiplier for exponential backoff
        jitter: Whether to add random jitter to backoff times

    Returns:
        The response object if successful, None if all retries fail
    """
    headers = headers or {}
    data = data or {}

    for attempt in range(max_retries + 1):
        try:
            response = requests.request(
                method=method,
                url=url,
                headers=headers,
                json=data,
                timeout=10  # 10 second timeout
            )

            # If successful, return the response
            if response.ok:
                return response

            # For 429 (Too Many Requests) or 5xx errors, we'll retry
            if response.status_code in (429, 500, 502, 503, 504):
                raise requests.exceptions.RequestException(f"Server error: {response.status_code}")

            # For other client errors (4xx), don't retry
            return None

        except requests.exceptions.RequestException as e:
            # Don't retry on connection errors if it's not the first attempt
            if attempt == max_retries:
                print(f"Max retries ({max_retries}) reached. Giving up.")
                return None

            # Calculate backoff time with exponential backoff and jitter
            backoff = min(initial_backoff * (backoff_multiplier ** attempt), max_backoff)
            if jitter:
                backoff = backoff * random.uniform(0.5, 1.5)  # Add 50% jitter

            print(f"Attempt {attempt + 1} failed. Retrying in {backoff:.2f} seconds...")
            time.sleep(backoff)

    return None
```

## Key Features:

1. **Exponential Backoff**: Waits longer between retries (1s, 2s, 4s, etc.) up to a maximum
2. **Jitter**: Adds randomness to backoff times to prevent thundering herd problems
3. **Selective Retries**:
   - Retries on 5xx errors and 429 (Too Many Requests)
   - Doesn't retry on most 4xx errors (client errors)
4. **Timeout**: Includes a 10-second timeout to prevent hanging
5. **Configurable**: All parameters can be adjusted as needed

## Example Usage:

```python
response = call_downstream_api(
    url="https://api.example.com/endpoint",
    method="POST",
    headers={"Content-Type": "application/json"},
    data={"key": "value"},
    max_retries=3,
    initial_backoff=0.5
)

if response:
    print("Success:", response.json())
else:
    print("Failed after all retries")
```

This implementation follows best practices for making HTTP calls to potentially unreliable services while being respectful of the downstream API's capacity.
