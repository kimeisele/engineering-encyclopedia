# HTTP API Caller with Backoff and Retry Logic

Here's a Python function that calls a downstream HTTP API with proper backoff and retry logic to avoid hammering a downed service:

```python
import requests
import time
import random
from typing import Optional, Dict, Any

def call_downstream_api(
    url: str,
    method: str = "GET",
    headers: Optional[Dict[str, str]] = None,
    data: Optional[Dict[str, Any]] = None,
    max_retries: int = 5,
    initial_backoff: float = 1.0,
    max_backoff: float = 30.0,
    backoff_multiplier: float = 2.0,
    timeout: float = 10.0
) -> Optional[requests.Response]:
    """
    Calls a downstream HTTP API with exponential backoff retry logic.

    Args:
        url: The API endpoint URL
        method: HTTP method (GET, POST, etc.)
        headers: Optional request headers
        data: Optional request body data
        max_retries: Maximum number of retry attempts
        initial_backoff: Initial backoff time in seconds
        max_backoff: Maximum backoff time in seconds
        backoff_multiplier: Multiplier for exponential backoff
        timeout: Request timeout in seconds

    Returns:
        requests.Response if successful, None if all retries fail
    """
    headers = headers or {}
    data = data or {}

    for attempt in range(max_retries + 1):
        try:
            response = requests.request(
                method=method,
                url=url,
                headers=headers,
                json=data,
                timeout=timeout
            )

            # Check for successful response (2xx status code)
            if response.ok:
                return response

            # For 4xx errors (except 429 Too Many Requests), don't retry
            if 400 <= response.status_code < 500 and response.status_code != 429:
                return response

        except (requests.ConnectionError, requests.Timeout) as e:
            # Only retry on connection errors or timeouts
            if attempt == max_retries:
                print(f"Max retries ({max_retries}) exceeded. Last error: {str(e)}")
                return None

            # Calculate backoff with jitter to prevent thundering herd
            backoff = min(initial_backoff * (backoff_multiplier ** attempt), max_backoff)
            jitter = random.uniform(0, backoff * 0.1)  # Add 10% jitter
            sleep_time = backoff + jitter

            print(f"Attempt {attempt + 1} failed. Retrying in {sleep_time:.2f} seconds...")
            time.sleep(sleep_time)

    return None
```

## Key Features:

1. **Exponential Backoff**: Waits progressively longer between retries (1s, 2s, 4s, etc.)
2. **Jitter**: Adds randomness to prevent synchronized retries from multiple clients
3. **Smart Retry Logic**:
   - Retries on connection errors and timeouts
   - Doesn't retry on most 4xx errors (except 429 Too Many Requests)
   - Gives up after max_retries attempts
4. **Configurable Parameters**:
   - Maximum retry attempts
   - Initial and maximum backoff times
   - Backoff multiplier
   - Request timeout

## Example Usage:

```python
response = call_downstream_api(
    url="https://api.example.com/data",
    method="POST",
    headers={"Authorization": "Bearer token123"},
    data={"key": "value"},
    max_retries=3,
    initial_backoff=0.5
)

if response:
    print("API call successful:", response.json())
else:
    print("API call failed after all retries")
```

This implementation follows best practices for making HTTP calls to potentially unreliable services while being considerate of the downstream service's health.
