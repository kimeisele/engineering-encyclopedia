# HTTP API Caller with Backoff and Retry Logic

Here's a Python function that calls a downstream HTTP API with proper backoff and retry logic to avoid hammering it when it's down:

```python
import time
import requests
from requests.exceptions import RequestException
from typing import Optional, Dict, Any, Callable

def call_downstream_api(
    url: str,
    method: str = "GET",
    headers: Optional[Dict[str, str]] = None,
    data: Optional[Dict[str, Any]] = None,
    max_retries: int = 5,
    initial_backoff: float = 1.0,
    max_backoff: float = 30.0,
    backoff_multiplier: float = 2.0,
    timeout: float = 10.0,
    retry_on_status: Optional[list] = None
) -> Optional[Dict[str, Any]]:
    """
    Calls a downstream HTTP API with exponential backoff retry logic.

    Args:
        url: The API endpoint URL
        method: HTTP method (GET, POST, etc.)
        headers: Optional request headers
        data: Optional request body data
        max_retries: Maximum number of retry attempts
        initial_backoff: Initial backoff time in seconds
        max_backoff: Maximum backoff time in seconds
        backoff_multiplier: Multiplier for exponential backoff
        timeout: Request timeout in seconds
        retry_on_status: List of HTTP status codes to retry on (None means retry on all errors)

    Returns:
        Response JSON if successful, None if all retries fail
    """
    headers = headers or {}
    retry_on_status = retry_on_status or []

    for attempt in range(max_retries + 1):
        try:
            response = requests.request(
                method=method,
                url=url,
                headers=headers,
                json=data,
                timeout=timeout
            )

            # Check if we should retry based on status code
            if response.status_code in retry_on_status:
                raise RequestException(f"Received status code {response.status_code}")

            # If successful, return the JSON response
            response.raise_for_status()
            return response.json()

        except RequestException as e:
            if attempt == max_retries:
                print(f"Max retries ({max_retries}) exceeded for {url}. Last error: {str(e)}")
                return None

            # Calculate backoff time with exponential delay
            backoff = min(initial_backoff * (backoff_multiplier ** attempt), max_backoff)
            print(f"Attempt {attempt + 1} failed for {url}. Retrying in {backoff:.2f} seconds. Error: {str(e)}")

            time.sleep(backoff)

    return None
```

## Key Features:

1. **Exponential Backoff**: Waits progressively longer between retries (1s, 2s, 4s, etc.) up to a maximum
2. **Configurable Retries**: Can specify maximum number of retry attempts
3. **Error Handling**: Catches all request exceptions and handles them appropriately
4. **Status Code Handling**: Can be configured to retry on specific HTTP status codes
5. **Timeout Protection**: Prevents hanging on unresponsive servers
6. **Type Hints**: Includes Python type hints for better code clarity

## Example Usage:

```python
# Basic GET request
result = call_downstream_api("https://api.example.com/data")

# POST request with custom headers and retry on 5xx errors
result = call_downstream_api(
    url="https://api.example.com/create",
    method="POST",
    headers={"Authorization": "Bearer token123"},
    data={"key": "value"},
    retry_on_status=[500, 502, 503, 504]
)
```

This implementation follows best practices for making resilient HTTP calls while being considerate to downstream services that might be experiencing issues.
