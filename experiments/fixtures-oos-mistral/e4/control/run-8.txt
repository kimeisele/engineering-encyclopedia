# HTTP API Caller with Backoff and Retry Logic

Here's a Python function that calls a downstream HTTP API with proper backoff and retry logic to avoid hammering a downed service:

```python
import time
import requests
from requests.exceptions import RequestException
from typing import Optional, Dict, Any

def call_downstream_api(
    url: str,
    method: str = "GET",
    headers: Optional[Dict[str, str]] = None,
    body: Optional[Dict[str, Any]] = None,
    max_retries: int = 5,
    initial_backoff: float = 1.0,
    backoff_factor: float = 2.0,
    timeout: int = 10
) -> Optional[Dict[str, Any]]:
    """
    Calls a downstream HTTP API with exponential backoff retry logic.

    Args:
        url: The API endpoint URL
        method: HTTP method (GET, POST, etc.)
        headers: Optional request headers
        body: Optional request body
        max_retries: Maximum number of retry attempts
        initial_backoff: Initial backoff time in seconds
        backoff_factor: Multiplier for exponential backoff
        timeout: Request timeout in seconds

    Returns:
        Parsed JSON response if successful, None otherwise
    """
    headers = headers or {}
    headers.setdefault("Content-Type", "application/json")

    retry_count = 0
    backoff = initial_backoff

    while retry_count <= max_retries:
        try:
            response = requests.request(
                method=method,
                url=url,
                headers=headers,
                json=body,
                timeout=timeout
            )

            # Check for successful response
            response.raise_for_status()

            # Return parsed JSON if successful
            return response.json()

        except RequestException as e:
            retry_count += 1

            # Don't retry on client errors (4xx) except 429 (Too Many Requests)
            if isinstance(e, requests.exceptions.HTTPError) and 400 <= e.response.status_code < 500:
                if e.response.status_code != 429:
                    print(f"Client error {e.response.status_code} - not retrying")
                    return None

            # If we've exhausted retries, return None
            if retry_count > max_retries:
                print(f"Max retries ({max_retries}) exceeded")
                return None

            # Exponential backoff with jitter to avoid thundering herd
            sleep_time = backoff * (1 + 0.1 * (2 * (retry_count / max_retries) - 1))
            print(f"Attempt {retry_count}/{max_retries} failed. Retrying in {sleep_time:.2f}s...")
            time.sleep(sleep_time)

            # Increase backoff for next retry
            backoff *= backoff_factor

    return None
```

## Key Features:

1. **Exponential Backoff**: Waits longer between retries (1s, 2s, 4s, etc.) to avoid overwhelming the service
2. **Jitter**: Adds slight randomness to backoff times to prevent thundering herd problems
3. **Smart Retry Logic**:
   - Doesn't retry on most 4xx errors (client errors)
   - Does retry on 5xx errors and 429 (Too Many Requests)
4. **Configurable Parameters**:
   - Maximum retry attempts
   - Initial backoff time
   - Backoff multiplier
   - Timeout settings
5. **Error Handling**: Properly handles network errors and HTTP errors

## Example Usage:

```python
# Successful call
result = call_downstream_api("https://api.example.com/data")
if result:
    print("API call succeeded:", result)

# Call with POST and body
payload = {"key": "value"}
headers = {"Authorization": "Bearer token123"}
result = call_downstream_api(
    "https://api.example.com/create",
    method="POST",
    headers=headers,
    body=payload
)
```

This implementation follows best practices for making HTTP calls to downstream services while protecting both your system and the downstream service from excessive load during outages.
