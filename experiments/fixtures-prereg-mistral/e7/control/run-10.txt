# Shared Counter with Thread-Safe Updates

Here's a Python implementation of a shared counter that uses a lock to ensure thread-safe updates. This prevents lost updates when multiple workers try to increment the counter simultaneously.

```python
import threading

class SharedCounter:
    def __init__(self, initial_value=0):
        self.value = initial_value
        self.lock = threading.Lock()

    def increment(self, amount=1):
        """Thread-safe increment of the counter"""
        with self.lock:
            self.value += amount
            return self.value

    def get_value(self):
        """Thread-safe read of the counter"""
        with self.lock:
            return self.value
```

## Alternative Implementation Using Atomic Operations

For Python 3.10+, you could also use the `threading` module's atomic operations:

```python
import threading

class SharedCounter:
    def __init__(self, initial_value=0):
        self._value = initial_value
        self._lock = threading.Lock()

    def increment(self, amount=1):
        """Thread-safe increment using atomic operations"""
        with self._lock:
            self._value += amount
            return self._value

    def get_value(self):
        """Thread-safe read"""
        with self._lock:
            return self._value
```

## Usage Example

```python
def worker(counter, increments):
    for _ in range(increments):
        counter.increment()

# Create a shared counter
counter = SharedCounter()

# Create and start multiple worker threads
threads = []
for _ in range(10):
    t = threading.Thread(target=worker, args=(counter, 1000))
    threads.append(t)
    t.start()

# Wait for all threads to complete
for t in threads:
    t.join()

print(f"Final counter value: {counter.get_value()}")  # Should be 10,000
```

## Alternative Conflict Detection Strategy

If you prefer a lock-free approach with conflict detection (like using atomic compare-and-swap), you could implement it like this:

```python
import threading
import time

class LockFreeCounter:
    def __init__(self, initial_value=0):
        self._value = initial_value
        self._version = 0

    def increment(self, amount=1):
        while True:
            current_value = self._value
            current_version = self._version

            # Simulate some work
            time.sleep(0.001)

            # Try to commit the update
            if self._version == current_version:
                self._value = current_value + amount
                self._version += 1
                return self._value
            # Else, retry
```

The lock-based approach is generally preferred for simple counters because:
1. It's easier to understand and maintain
2. It provides strong consistency guarantees
3. The overhead of acquiring/releasing locks is minimal for simple operations

The lock-free approach can be more performant in high-contention scenarios but is more complex to implement correctly.
